# iOS end-to-end flows (Maestro)

These drive a **real iOS simulator** against the PR's own Vercel preview. That
is the whole point of them, and the reason they exist instead of a React Native
Testing Library suite: RNTL renders a component tree in JavaScript with no
layout engine and no keyboard. It can prove the composer *exists*. It cannot
prove you can see it while typing, which is exactly the bug that shipped
(`d316cd6`, 2026-08-27) and exactly what these flows assert.

## What they cover

| Flow | Asserts |
|---|---|
| `sign-in.yaml` | The real OTP sign-in, end to end, against the preview API. |
| `chat-keyboard.yaml` | The regression: composer reachable and operable **while the keyboard is up**. |

`chat-keyboard.yaml` is a guard test, so it is held to the repo's standard for
one — see *"New guard tests: mutation-check them"* in CLAUDE.md. Reintroduce the
bug (put the `KeyboardAvoidingView` back inside `ChatPanel`), watch this flow go
red, restore. **A guard nobody has watched fail is decoration.**

## Running locally

Needs macOS with Xcode and a booted simulator; Maestro cannot run on Linux.

```bash
brew install maestro                      # or: curl -Ls https://get.maestro.mobile.dev | bash
node scripts/ios-e2e-fixture.mjs --base-url https://<preview>   # prints EMAIL/CODE
maestro test mobile/maestro \
  -e APP_ID=com.feraltravels.app \
  -e EMAIL=<from the script> \
  -e CODE=<from the script>
```

## Why the fixture user is minted outside the app

The app has no way to read its own sign-in email, and the flows must not depend
on a mailbox — the suite already learned that lesson twice (MailSlurp expired,
Workspace IMAP never authenticated; see the E2E section of CLAUDE.md). So the
workflow seeds a fixture account over the same guarded `/api/test/*` endpoints
the Playwright suite uses, reads that address's own code, and hands it to
Maestro as `${CODE}`.

Nothing is bypassed. The code is generated by the real `sendOtpCode`, stored
with its real expiry, and checked by the real verifier through the app's real
six-box form. `/api/test/otp` replaces the inbox, not a step of authentication,
and it refuses any address outside `FIXTURE_EMAIL_PATTERN`.
