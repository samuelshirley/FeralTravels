`CLAUDE.md` names every file in `scripts/` (its index guard requires that). This file
is the rationale: why each exists, what it measures, and the traps.

### Scripts (`scripts/`)

Fourteen of those were missing from this list until 2026-09-09, which is what `claudeMdGuard.test.ts` now prevents — an index nobody can trust is worse than no index, because the reader cannot tell "not listed" from "does not exist". One line each, in the order above: **`check-env.sh`** / **`check-preview-env.mjs`** assert the required env vars are present locally and in the Vercel preview environment (the second runs in CI, and is where a missing `ANTHROPIC_API_KEY_CI` is caught). **`debug-trip.ts`** and **`extract-canonical-trip.ts`** are read-only trip dumps that predate `dump-trip.ts`. **`e2e-pr-summary.mjs`** renders the Playwright results table into the sticky PR comment. **`generate-apple-client-secret.ts`** mints the Apple OAuth client secret JWT (it expires; regenerate before it does). **`handoff-bug-campaign.sh`** drives the onboarding-handoff repro. **`iap-preflight.sh`** checks what App Store Connect / RevenueCat still need before a purchase can work, and **`iap-webhook-secret.sh`** generates the RevenueCat shared secret and sets it on Vercel production. **`make-test-user.ts`** and **`trial-account.ts`** mint the disposable paywall accounts (see the `sam+trial-<tag>@` note under Subscriptions). **`prune-branches.sh`** deletes merged local branches. **`serverOnlyStub.ts`** is the no-op `server-only` shim `tsconfig.scripts.json` points at so a `tsx` script can import server modules. **`set-ios-oauth-client-id.mjs`** writes the Google iOS client id into the Vercel envs. **`claude-task.sh`** hands a brief under `docs/tasks/` to Claude Code as its opening prompt. **`measure-message-gate.ts`** runs 25 real production messages and 25 written as junk through the message gate and reports the tier, the decider, the false-positive count and the classifier cost — read-only, and on the CI key.

**`anthropic-usage-report.ts`** (2026-09-09) pulls the org's real spend from the Anthropic **Admin API** (`/v1/organizations/usage_report/messages` grouped by `api_key_id`+`model`, `/v1/organizations/cost_report` grouped by `description`, `/v1/organizations/api_keys` for names) and lays it beside prod `usage_events` day by day. `npx tsx scripts/anthropic-usage-report.ts [--from YYYY-MM-DD] [--to YYYY-MM-DD] [--json]`; needs `ANTHROPIC_ADMIN_KEY` (an **Organization-scoped** key: platform.claude.com/settings/keys → Create key → Scope: Organization — there is no "Admin keys" page in this org, that URL 404s, and a workspace-scoped key like the app's is refused) plus `DATABASE_URL`, read-only. It exists because the admin panel CANNOT be reconciled from the database: for Sep 1–8 the Console billed $21.94 and prod `usage_events` held $1.80 (8%), and the missing 92% was written by CI previews and `next dev` into databases that no longer exist. Anthropic is the only complete record. **First run (2026-09-09, Sep 1–8): our `estimateAnthropicCostUsd` on the Console's token counts matched the billed amount to the cent on every day and every line item** — the accounting math is exact; the gap is coverage (rows written to deleted preview DBs) and attribution (see the CI-key note above). `cost_report.amount` is in CENTS despite the reference page's example (the sum read 2194.03 against a $21.94 Console total). Requires the org to be a TEAM organization — the Admin API refuses "Sam's Individual Org" with `permission_error` on every endpoint, including `/organizations/me`; Organization settings → Organization → Convert to team fixed it, no plan change. Its tables separate the two discrepancies a single total conflates — **rows missing** (Console tokens ≫ prod tokens, per model) from **price wrong** (our `estimateAnthropicCostUsd` applied to the Console's OWN token counts vs the Console's billed amount, and each billed line item backed out to an effective $/MTok beside our pricing table) — and the per-key table is what `ANTHROPIC_API_KEY_CI` was split for. `scripts/reconcile-anthropic-spend.ts` remains the DB-only view.

**`dump-trip.ts`** (2026-09-08) prints one trip's rows — the trip row, every leg with its fuel status, the whole `chat_history` transcript with kinds, the `penny_turns` rows and per-provider usage. `npx tsx scripts/dump-trip.ts "National Park Tour"` (name match, or a uuid; `--json` for the raw shape; **`--trace` opens each turn's tool inputs and results out in full**, which is what an actual investigation needs and what nobody wants on every dump — one truncated line per tool call prints by default). Read-only, `DATABASE_URL` from `.env`, and a name matching more than one trip prints the candidates rather than guessing. It exists because a bug report arrives as a screenshot and the first question is always what the database actually holds: it is what showed that the "nothing in chat" report was a turn that ran **3m15s** and landed correctly, not a lost message. Builds its own `postgres` client like `lifetime-spend.ts` — `src/server/db/client.ts` is `server-only` and throws under tsx.

**`decide-mobile-release.mjs`** (2026-08-27) owns the OTA-vs-native-build call that `.github/workflows/mobile.yml` used to make with a regex in a `run:` block. `node scripts/decide-mobile-release.mjs --base <ref> --head <ref>` prints one word on stdout (`native` / `js-only`) and its reasoning on stderr. It exists because file-level matching classified a merge whose ONLY change to `mobile/package.json` was a `scripts` entry (`sync:shared`) as native — the lockfile was untouched, proving no dependency moved — costing ~30 min of EAS queue, a build credit, and the OTA for fifteen JS files, which that path deliberately skips. `mobile/package.json` is now judged by CONTENT against an **allowlist of provably-inert top-level keys** (`name`, `version`, `private`, `description`, plus `scripts` EXCEPT npm/EAS lifecycle hooks — a `postinstall` can patch native source). Everything else, including a key invented tomorrow, defaults to native; so does every failure path (unreadable file, unparseable JSON either side, `git show` error, no usable base). `mobile/package-lock.json` remains an unconditional native signal on its own. `app.config.js`, `eas.json` and `assets/**` stay file-level. **`version` in `mobile/package.json` is inert only because `app.config.js` hardcodes its own `version: '1.0.0'`** — if that ever starts reading package.json, drop `version` from the allowlist in the same commit. `--json` swaps stdout for `{decision, reasons}`, which is what the PR-comment step renders. Guarded by `src/lib/decideMobileRelease.test.ts` (30 tests), which also fails if `mobile.yml` stops RUNNING the script, reinstates an inline `package.json` regex, **loses the `if:` gate on the TestFlight build**, or stops forecasting on `pull_request`.

**`ios-e2e-local.sh`** runs the Maestro flows on a developer's own Mac, against a local server (`next dev` on 4310) and a **throwaway local Postgres on port 55432** — never the production database in `.env`, which is what `/api/test/seed` would otherwise write fixture users into. Docker (`docker-compose.e2e.yml`) is the default; a Homebrew `postgresql@16` is the fallback, because Docker Desktop is a GUI install with a licence prompt and a Mac without it should still be able to run these flows. **An EMPTY database is bootstrapped with `drizzle-kit push` + `seed-migration-journal.ts`, not by replaying `drizzle/*.sql`** — the SQL chain cannot run from empty and never could (`0005_mute_meltdown` and `0006_nightly_replan` both create the `trip_status` type and column, the second unguarded; `0002_magical_joystick` calls `setval(seq, 0)` on an empty `chat_history`). Nothing noticed because production was itself bootstrapped with push and CI's preview is a copy-on-write clone of it, so both only ever apply the newest file. A database that already has tables still takes the normal `db:migrate`. It exists because the flows in `mobile/maestro/` were merged **having never once been executed**, and their only feedback channel was an 18-minute macOS CI job that reported all three of its failure layers with the same line and uploaded an empty artifact. `all` runs `doctor → up → build → launch → sign-in → chat-keyboard` and stops at the first failure, so the output names the LAYER; `run <flow>` re-runs one in about a minute. Everything a run produces goes to `mobile/maestro/.local-run/` (gitignored): the JUnit report, Maestro's `commands-*.json` (the only file that says which yaml step died — the JUnit says `Unknown error`), `maestro.log`, screenshots, and the server log. `hierarchy` dumps the live view tree so a selector is fixed from what the app renders rather than from what the source suggests. `doctor` refuses to continue on an Xcode below 26 and prints the `xcode-select` line, because that specific mismatch presents as a timeout. **`storekit` and `xcode` (2026-09-01)** are the in-app-purchase half of the same loop: `storekit` copies `mobile/storekit/FeralTravels.storekit` beside the generated `.xcodeproj` and writes a `StoreKitConfigurationFileReference` into the scheme's Launch AND Test actions (idempotent; `build` calls it, because `expo prebuild --clean` rewrites the scheme every time), and `xcode` opens the workspace so a purchase can be driven by hand. Maestro cannot drive one — the configuration is activated by the scheme's launch action and Maestro installs the `.app` and launches it outside any scheme, and there is no `simctl storekit` subcommand as of Xcode 26.6 (checked with `simctl help`, not assumed).

**`sim-frames.swift`** (2026-09-08) measures a simulator screen recording frame by frame with nothing installed — it scans one pixel column per frame for the code box's border, fill and glyph rows, so a layer lagging by two frames shows up as a column of integers rather than a feeling. Compile with `swiftc`; the header has the recording incantation. Written to test the border-lag hypothesis in `docs/bugs/native-ui-fabric-artifacts.md`, which it did not reproduce (glyph-to-border offset constant to ±1 px across the whole keyboard rise).

**`set-paywall-flag.mjs`** (2026-09-03) writes `app_meta.paywall_enabled` directly — `node scripts/set-paywall-flag.mjs on|off`, `DATABASE_URL` from the environment. It exists for CI: the tested preview must have enforcement ON or `e2e/subscriptions.spec.ts` asserts against a paywall that never fires, and the switch stopped being an env var on 2026-09-02. It reads the row back rather than trusting the write, because "I asked for on" is a weaker claim than "it is on" in a CI log. **The admin UI is the normal way to flip it** and records who pressed it; this does not, which is why it is a CI tool rather than an ops one.

**`pick-ios-simulator.mjs`** chooses the simulator both CI and the local script boot: the newest iOS runtime on the machine, discovered rather than pinned. Neither the device model nor the runtime is hardcoded anywhere — a named model is how the job breaks silently the month the runner image drops it, and taking whatever `simctl` lists first picked an iOS 18.5 device for a driver built against 26.2.

**`pick-screenshot-simulator.mjs`** (2026-09-02) is the DELIBERATE opposite of the file above, and the difference is the point: a test flow wants any iPhone that boots, so pinning a model is how the job breaks the month the runner drops it — but a SCREENSHOT is defined by its pixel dimensions, and App Store Connect rejects an image that is not one of the sizes it expects for the slot, so there the model IS the requirement. Each slot holds a list of models newest-first and the first one installed wins, so a dropped model costs a line rather than the command; an empty list errors with the `simctl create` invocation rather than a stack trace. Only the **6.9-inch** slot is required (`supportsTablet: false` means no iPad slot at all, and Apple scales 6.9" down for smaller iPhones). It also carries the correction that made it necessary: §3 of `docs/design/app-store-listing.md` said to capture 1290x2796 from an **iPhone 17 Pro**, and those two do not go together — the 17 Pro is the 6.3" device at 1206x2622, so that instruction produced a set Apple refuses.

**`ios-e2e-fixture.mjs`** mints the account the Maestro flows sign in as: seeds the canonical graph over `/api/test/seed`, calls the app's OWN `/api/mobile/otp/send`, polls `/api/test/otp` for the code, and prints `EMAIL`/`CODE`. It exists so the iOS flows never depend on a mailbox — this suite has been switched off by a third-party inbox twice (MailSlurp's expired trial, a Workspace IMAP that never authenticated), and the rule that came out of it is that the pipeline does not rest on a vendor who can turn it off. Nothing is bypassed: `sendOtpCode` really runs, the code carries its real expiry, and the app types it into the real six-box form for the real `verifyOtpCode`. It replaces the INBOX, not a step of authentication. `--trip-name` / `--vehicle-name` / `--user-name` default to the `E2E Fixture …` literals and are overridden by ONE caller — `ios-e2e-local.sh screenshots`, which seeds the identical two legs under names a customer could read. `sign-in.yaml` and `chat-keyboard.yaml` therefore match the trip card against `${TRIP_NAME}` rather than a literal.

(E2E fixtures are seeded/cleaned over HTTP via `/api/test/*` from `global-setup.ts`/`global-teardown.ts` — the old `seed-e2e-fixture.ts` / `cleanup-e2e.ts` SQL scripts + `e2e:seed`/`e2e:cleanup` npm scripts were removed.)
